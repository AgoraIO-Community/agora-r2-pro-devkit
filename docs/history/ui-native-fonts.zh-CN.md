# 0.1.1 原生分辨率文字渲染

> 历史记录：本文保留对应阶段的判断、路径和命令，不作为当前操作指南。现行入口见[文档索引](../README.md)，结果以[验证状态](../validation/README.md)为准。

0.1.0 默认 `./run.sh` 的业务流程已由用户在 RV1126B 上验证通过，英文文字的块状感是本次优化对象。0.1.1 使用原生 640×480 画布，取消整帧两倍像素复制，输出层仅进行旋转。

## 字库与排版

全部字体从固定版本的 TTF/OTF 重新栅格化，使用 4 bpp、16 级灰度覆盖度。字体源、SHA256、字形集合和工具版本记录在 `ui/fonts/sources.json`。目标程序直接编译生成的 C 字库，运行时不依赖 Pillow 或 FreeType。

| 内容 | 0.1.0 | 0.1.1 |
| --- | --- | --- |
| 终端英文 | 9 px 字形放大两倍 | DejaVu Sans Mono Bold，原生 18 px，行高 24 px |
| `</>` 签名 | 10 px 字形放大两倍 | 同族原生 20 px，行高 26 px |
| 中文与流程提示 | 20 px 字形放大两倍 | Source Han Sans SC Normal，原生 40 px，行高 52 px |
| 配对码 | Montserrat 32 px 放大两倍 | Montserrat Medium，原生 64 px，行高 70 px |

终端保留四行，行距为 26 px，标签宽度增至 419 px；最长的 `> state: in_conversation | vp:pending` 可完整显示。配对码按字符串处理，保留前导零。

像素镜框继续采用两像素网格，避免独立取整在相邻矩形之间产生细缝。眼睛与嘴部沿用原有图形、颜色和状态策略。DRM 刷新仍支持四种旋转与局部矩形，并按物理行连续写入 framebuffer，保留驱动返回的 pitch。

## 资源与检查

画布从 307,200 字节增至 1,228,800 字节，32 行绘制缓冲从 40,960 增至 81,920 字节，两者合计增加 962,560 字节（约 0.92 MiB）。DRM framebuffer 尺寸没有变化；字库位图另约 162 KiB，不含描述符。

主机检查覆盖原生像素旋转、行填充、局部刷新、文字在屏幕内的范围、字形存在性、最长终端行、两种语言的流程文案、前导零配对码，以及 23 个表情。

实际输出还检查英文区域的 2×2 像素块：整帧两倍复制会使某种网格对齐下所有文字块都一致；新版在四种对齐中取最大值，实测约 0.116，并要求低于 0.9。这是针对重复放大的回归检查，不是显示质量评分。

普通和 UBSan 检查结果，以及 AArch64 构建结果见 `validation.zh-CN.md`。用户已完成 0.1.1 真机测试并确认显示效果满足需求；长时间语音/动画并发稳定性仍需专项验证。

## 重新生成字库

生成依赖 Pillow 10.2.0 和 FreeType 2.13.2；已生成的 C 文件随源码保留，正常编译不需要安装这些工具。将 `sources.json` 中对应哈希的字体文件放入 `local/fonts/` 后执行：

```sh
local/font-tools/bin/python scripts/generate-ui-fonts.py
local/font-tools/bin/python scripts/generate-ui-fonts.py --check
```

本次生成工具环境为 Python 3.10 + Pillow 10.2.0。英文源文件取自 Matplotlib 3.8.2 的 DejaVu 字体副本，并与其官方 wheel 中的相同文件逐字节核对；中文源文件与 0.1.0 字库记录的输入 SHA256 一致。保留 Bitstream Vera 和 SIL OFL 许可，生成字体使用 MyBot 派生名称。

## 上板对比

新包名称为 `mybot-rv1126b-0.1.1-aarch64.tar.gz`，使用 `first-validation.zh-CN.md` 中的升级步骤。先结束 0.1.0 进程，新版沿用同一个 KV 目录和身份派生方式，服务与身份配置相同时可复用绑定。

建议先运行 `./run.sh --ui-demo --run-seconds 50` 检查英文、颜色、方向和表情，再运行 `./run.sh` 对比真实状态文字和配对页，并观察语音与 UI 同时工作时的连续性。原 0.1.0 测试包保留，可退出新进程后从原目录恢复验证。
