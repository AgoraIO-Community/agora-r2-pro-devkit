# AP Wi-Fi 配网

应用内置 AP 配网与语音引导，并在配网完成后检查系统时间。正常开机时，已有可用路由就直接启动业务。如果无线接口或系统 `wpa_supplicant` 控制端尚未就绪，设备显示“等待网络”，最多等 15 秒。接口和控制端就绪后，若系统托管了已保存的网络，设备再给系统最多 5 秒完成选网和 DHCP。等待期间系统自行联网就直接沿用。仍无路由时，应用在另一个共计 30 秒的窗口内尝试已保存网络。没有已保存网络或尝试失败时，设备开启配网热点。

在设置中选择“设备配网”或确认恢复出厂后，即使系统已有路由，也会在无线接口和控制端就绪后进入 AP。热点与门户就绪后屏幕才显示热点名。设备 AP、本机 HTTP 提交保存及业务恢复的验证记录，以及手机无线、DHCP、captive browser 和语音的验收范围，见[验证矩阵](../validation/README.md)。

## 设备前提

目标 Linux 系统需要：

- 支持 nl80211 AP 模式的 Wi-Fi 驱动；优先支持同一射频上的 AP+STA 虚拟接口组合。
- 可执行的 `ip`、`iw`、`hostapd`、`dnsmasq`、`wpa_supplicant`、`udhcpc`，以及 DHCP hook 使用的基础 shell 工具。运行包只内置 `assets/wifi/udhcpc.script`，不包含这些系统程序。
- 创建/配置网络接口、启动 DHCP、使用私有 `/run` 目录和绑定 HTTP 80、DNS 53 端口的权限。通常由 root 运行；不自动安装软件或更改系统服务。
- 正常的系统时间和 CA 配置，供后续 HTTPS 配对和 MyBot 服务使用。

可由设备操作者先检查：

```sh
for tool in ip iw hostapd dnsmasq wpa_supplicant udhcpc; do
    command -v "$tool" || break
done
iw dev
iw list
```

`iw list` 应列出 AP 模式；并发能力需结合 `valid interface combinations` 和实际启动确认。能列出 AP 不等于 AP+STA 能同时工作。若驱动不支持创建虚拟 AP，后端只在安全拥有 STA 的情况下退回单接口；已有外部 supplicant/hostapd 占用时明确报错，不会全局停止系统网络管理器。操作者需要按板级网络方案显式移交该接口，或使用仅监测模式。

## 手机操作

1. 正常运行 `./run.sh`；离线且无法恢复已保存网络时自动进入配网。已有网络时，点击右上角齿轮，再选择“设备配网”。热点与门户就绪后显示热点和访问地址，并播放一次语音引导；静音时不发声。
2. 手机连接开放热点 **`mybot-xxxx`**。`xxxx` 由所选 STA 完整永久 MAC 的 SHA-256 摘要派生，为四位小写十六进制。同一地址对应固定热点名，短后缀可能重复，请以设备屏幕为准；热点不设密码，按手机提示选择保持连接。
3. 等待 captive portal 弹出；未弹出时在浏览器打开 **`http://192.168.4.1/`**。
4. 从列表选择 2.4 GHz 网络，或手动填写网络名称以连接隐藏 SSID。输入密码；开放网络留空。页面支持中文/English 切换。
5. 点击连接并等待结果。候选连接在获取可用 IPv4 和路由后才保存；连接或保存失败时显示重试入口。系统 Wi-Fi 模式保存后还会等待最多 30 秒，确认目标网络的关联、租约与路由恢复稳定，期间页面保持“正在连接”；超时可重试，已经保存的网络仍保留。单接口模式在连接尝试期间会暂时关闭热点，失败后重新连接 `mybot-xxxx` 再打开页面即可重试。
6. 页面确认连接成功后显示“完成”，约 1 秒后请求退出配网。控制器收到退出请求后留出响应时间；即使浏览器离开，成功状态最多保持约 5 秒后自动结束。热点关闭，系统时间检查通过后 MyBot 恢复启动并继续原有配对/会话流程。单接口模式成功时手机可能先失去热点，直接观察设备恢复业务。

门户的“已保存的网络”支持设置默认与删除；默认网络在列表首位。最多保存 10 项，连接成功的新网络成为默认。删除默认项后，下一项成为默认；系统协作模式的列表以 `/etc/wpa_supplicant.conf` 为主记录，设置默认和删除会原子更新该记录并重载；私有模式仅更新应用自己的记录。

门户按故障阶段提供中英文提示：连接失败时检查网络与密码；已经连上但保存失败时检查设备存储；配置已保存但联网确认超时时保留该配置，并提示检查路由器后重试。更新已保存网络失败时刷新列表再重试。页面只读取固定错误分类，不显示后端诊断或凭据；切换语言会同时更新当前错误提示。

语音来自包内 `assets/locales/<MYBOT_LOCALE>/wificonfig.pcm`，默认语言与 UI 构建相同，支持 `zh-CN` 和 `en-US`；手机页面切换语言不会改变设备语音。提示音使用已保存输出音量，每次进入配网流程只播放一次，刷新页面、错误密码重试或单接口热点恢复不重复播报。离开 AP 或退出应用会取消播放、等待声卡释放后再恢复 SDK；播放资源或声卡失败会报告错误，不影响已可用的门户。

AP 配网期间不启动授时 helper，也不消耗授时等待窗口。完成配网、网络可用后，应用等待 OS 校时。默认窗口 30 秒，超时后仍会自动检测；校时通过后才启动云端业务。详见[系统时间与启动保护](time-sync.zh-CN.md)。

热点是临时开放网络；配网结束后自动关闭。SSID 和密码只通过本地 HTTP 请求正文提交，不放入 URL，也不写入应用日志。加密网络保存派生 PSK，存于私有 `MYBOT_KV_STORE_DIR/wifi/wifi.credentials`（文件 0600、目录 0700）；派生 PSK 仍属于敏感凭据，请勿上传或公开备份。

## 手动重新配网

点击右上角齿轮，再选择“设备配网”。这是手动配网的唯一入口，等待网络、AP 配网和首次绑定期间也可操作。应用主循环先停止 SDK 和当前会话，再进入 AP；完成后按既有绑定恢复 SDK，仍需短触或 Menu 短按显式开始会话。已经处于 AP 时显示现有配网指引，不重复启动热点。长按触屏或 Menu 键不会启动会话或配网。

```sh
# 指定配网无线接口；运行后通过 UI 设置进入手动配网
./run.sh --wifi-interface wlan0

# 由系统网络管理器负责联网，本应用只监测
./run.sh --no-wifi-provisioning
```

`RV1126B_WIFI_INTERFACE` 等价于 `--wifi-interface` 的环境默认值。`--interface` / `RV1126B_INTERFACE` 是 SDK 的网络监测/路由过滤条件，与配网接口分开；若过滤到另一没有网络的接口，配网成功也不能让 SDK 就绪。`--no-wifi-provisioning` 禁用自动和手动 AP 配网；关闭 UI 时没有手动配网入口，但仍保留离线自动配网。UI 演示不启动配网服务。

## 排查

| 现象 | 检查 |
| --- | --- |
| 缺少工具 / Missing required Wi-Fi tool | 由目标系统提供对应程序和兼容构建，确认 PATH；包内 DHCP hook 不代替系统工具 |
| 等待后仍提示 No nl80211 Wi-Fi interface | 运行 `iw dev` 检查是否出现无线接口，核对驱动和固件。若指定了 `--wifi-interface`，核对接口名。此时应用尚未尝试已保存的网络 |
| Driver cannot create an AP+STA interface | 查看驱动并发组合和现有接口；若外部管理服务拥有 STA，需要人工移交，应用不会抢占 |
| hostapd did not enable the AP | 检查监管域、2.4 GHz 信道、驱动和工具兼容性；现有 STA 位于 5/6 GHz 时先改用 2.4 GHz |
| 配网失败 / Wi-Fi setup failed | AP 辅助进程退出或热点无法启动时，撤销热点引导并保留设置菜单。检查对应错误日志和工具后，在设置中重新选择“设备配网”；应用不会无限自动重启热点，已保存网络保持不变。应用状态为 `wifi_error` |
| Cannot bind Wi-Fi portal sockets | 检查 `192.168.4.1` 已配置、80/53 端口占用与权限；避免与另一门户/DNS 服务抢占相同地址 |
| 热点可见但手机拿不到地址 | 检查 dnsmasq、驱动和手机 DHCP；这需要设备证据，主机测试不能代替 |
| 手机不弹页面 | 连接热点后手动打开 HTTP 地址，确认没有因“无互联网”提示自动切换回其他网络 |
| 扫描列表为空 | 单接口模式只读取扫描缓存，可手动输入 SSID；隐藏网络本来也可能不显示 |
| 错误密码后没有立即显示失败 | 一次连接有最多 30 秒预算；单接口模式需等待热点恢复后重新连接手机 |
| 门户可用但没有配网语音 | 检查保存音量是否为 0、`MYBOT_LOCALE`、`MYBOT_ASSETS_DIR` 对应的 `wificonfig.pcm`、播放设备与错误日志；语音失败不阻止手机配网 |
| 配网成功但业务不通 | 检查设备默认路由、DNS、时间、CA、服务地址及显式 SDK 接口过滤；获得路由并不证明云端服务可达 |
| 配网后提示系统时间无效或超时 | 保留已有校时服务，检查 DNS/NTP 网络与当前日期；授时窗口从退出 AP 且联网后计算，见系统时间指南 |
| 已连接但重启后不能复用 | 检查私有存储权限、可写性与退出附近错误；保存失败不会伪装成已持久化，不要通过删除绑定目录修复 |

## 设备验证

由操作者使用本候选包执行并记录。**独立 `MYBOT_KV_STORE_DIR` 只隔离应用绑定和私有数据，不隔离系统 Wi-Fi 或网络接口。** 不要删除正式目录来制造“首次启动”。

- **系统协作模式**：设置了 `MYBOT_SYSTEM_WPA_CONFIG` 时，正式网络主记录仍为该路径，通常是 `/etc/wpa_supplicant.conf`。即使更换 KV 目录，连接成功、设置默认或删除操作仍会修改它。使用专用测试镜像，或先在设备内私密备份系统 Wi-Fi 配置及板级网络策略，并准备可用的 ADB/恢复通道；按[部署指南](deployment.zh-CN.md)保留原绑定和回退材料。
- **私有模式**：在专用测试环境中不设置 `MYBOT_SYSTEM_WPA_CONFIG` 和系统租约事件目录 `MYBOT_DHCPCD_LEASE_DIR`，另设测试 KV 目录。仍须明确所选无线接口和网络管理器的归属；本应用不会抢占外部 supplicant/DHCP。更换存储目录不代表有权停止系统服务。

两种模式都会改变所选 Wi-Fi 接口的运行状态，私有模式也不是网络沙箱。先确认当前实际环境和接口归属，再测试无缓存、删除网络、错误密码或重启；不要通过继承正式服务配置进行破坏性“首次启动”模拟。

| 场景 | 通过条件 |
| --- | --- |
| 已有网络正常启动 | 无需配网即可恢复原有业务，不创建热点、不播放配网语音、不改动已有网络；缺少 AP 工具不影响已有网络启动 |
| 无缓存且无可用网络 | 显示热点/地址，手机取得地址，captive browser 或手动 HTTP 入口可访问 |
| 设置页手动配网 | 右上角齿轮 →“设备配网”开启配网；所选接口与 `--wifi-interface` 一致；等待网络和绑定时设置入口可用 |
| 错误密码与重试 | 页面有连接中状态；失败后可重试，正式缓存不被错误候选覆盖；单接口路径热点可恢复；同一配网流程不重复播报 |
| 正确密码 / 开放 / 隐藏网络 | 获得可用 IPv4 与路由后完成；正常退出热点并恢复业务；隐藏 SSID 可手工输入 |
| 保存与重启 | 候选成功后生成私有配置，重启可复用；设置默认/删除与列表一致，失败网络不写入缓存 |
| 会话中手动配网 | 设置中的“设备配网”先结束 SDK/音频/视频，再启动 AP；完成后绑定保持且可再次开聊 |
| 非配网手势与终端 | 长按触屏或 Menu 键、终端 `w` 均不进入 AP；长按松手不触发会话切换，短触和 Menu 短按仍正常切换会话 |
| 中英文与 captive browser | 手机页面切换语言，长/中文/引号 SSID 显示为文本；刷新、失败提示与完成行为正确 |
| 语音与保存音量 | 热点和门户就绪后才播报；暂不操作页面时能完整播完一次；`MYBOT_LOCALE=zh-CN` / `en-US` 对应正确语音，沿用保存音量，0 时静音 |
| 播放取消与故障 | 播放期间成功离开 AP 或 Ctrl-C/SIGTERM 能取消并回收声卡，之后 SDK/再次启动音频正常；资源缺失或声卡失败有错误报告，门户仍可用 |
| 退出与清理 | 配网中 Ctrl-C/SIGTERM 能退出；本应用 HTTP/DNS、AP、DHCP 与拥有的子进程清理，外部服务仍运行，再次启动无端口/接口残留 |
| 升级/回退 | 原绑定不丢失，两个版本不可同时运行；使用旧版时保留新增加的私有 Wi-Fi 缓存 |

记录版本/commit、包 SHA256、板型、系统、无线芯片/驱动、`iw` 并发能力、工具版本、实际命令、手机系统/浏览器、所走 AP+STA/单接口路径和结果。公开日志前移除 token、密码、派生 PSK、配对码、设备标识及完整 SSID/MAC。
